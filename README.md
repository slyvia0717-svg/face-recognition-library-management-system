# 古典风格 · 人脸识别自助图书管理系统

以中国古典风格呈现的自助借阅应用。使用 Vue 3、Express 与 SQLite，实现账号与权限控制、人脸录入与登录、真实扫码借书、还书和管理员维护。界面沿用水墨山水、书法标题及读书熊猫/小猫插画，支持电脑与手机布局。

此版本在原项目基础上迭代，具体来源与改进见 [来源说明](docs/ATTRIBUTION.md)。

## 已实现功能

| 模块 | 功能 |
| --- | --- |
| 账号与权限 | 注册、密码登录、退出；普通用户与管理员权限隔离；8 小时服务端会话 |
| 个人信息 | 修改本人昵称、姓名、电话；改名后借阅与人脸记录仍绑定固定账号 ID |
| 人脸验证 | 密码确认后录入、重新录入和删除；服务端提取 128 维特征并进行 1:1 比对 |
| 自助借还 | 二维码及常见条形码解码、精确查书、确认借阅、归还个人借阅单 |
| 馆藏管理 | 添加与编辑图书、设置唯一编号、库存联动、下架保护、测试二维码下载 |
| 人员与记录 | 管理员维护人员与借阅记录，查看归还状态及每日借还统计 |
| 数据一致性 | SQLite 事务、最后一本书的并发保护、借阅重试幂等、重复归还保护 |

密码使用带随机盐的 scrypt 哈希；人脸特征使用 AES-256-GCM 加密。浏览器提交照片，由服务端完成比对，不能直接提交“识别成功”或特征向量获取会话。

## 技术栈与结构

- 前端：Vue 3、Vue Router、Element Plus、Axios。
- 后端：Node.js、Express、SQLite、Joi。
- 人脸：face-api.js / TensorFlow.js，独立工作线程执行 CPU 推理。
- 扫码：vue-qrcode-reader 与本地 ZXing WASM；二维码由 qrcode 生成。

```text
.
├── backend/                 # API、身份验证、事务与人脸推理
│   └── test/                # 隔离数据库的回归测试与公开模型样本
├── frontend/
│   ├── src/                 # 页面、共享导航、摄像头与古典主题
│   └── public/
│       ├── models/          # 实际使用的三类模型及权重分片
│       └── wasm/            # 本地扫码解码器及许可说明
├── data/.gitkeep            # 运行时生成数据库与密钥，内容不提交
└── docs/                    # 使用、设计与来源说明
```

## 本地启动

需要 Node.js 与 npm。此发布目录在 Node.js 24 / npm 11 环境验证；安装 SQLite 的原生依赖时，需要可用的预编译包或本机构建工具。

先安装前后端依赖。在项目根目录执行：

```sh
npm ci --prefix backend
npm ci --prefix frontend
```

初始化管理员密码，然后启动后端：

```sh
cd backend
npm run set-password -- admin
npm start
```

命令会隐藏密码输入。管理员昵称为 `admin`，**没有默认密码**；密码为 8–128 个字符。密码重置会撤销该账号现有会话，并删除其人脸凭据。

另开终端，在项目根目录启动前端：

```sh
npm run serve --prefix frontend
```

打开终端显示的地址，默认是 `http://localhost:8080`。前端开发服务器将 `/api` 代理至 `http://localhost:3000`。新数据库会生成六本演示图书及其内部编号，不包含任何真实用户资料。

## 推荐体验流程

1. 注册借阅者账号，使用密码登录。
2. 在个人中心修改昵称、姓名或电话。
3. 打开“人脸识别设置”，输入当前密码，拍摄并录入本人。
4. 退出，填写当前昵称，通过“人脸登录”验证。
5. 在借书页打开测试二维码，用另一台设备展示图书码，再使用摄像头扫码并确认借阅；摄像头不可用时可手动输入编号。
6. 查看个人借阅记录，在归还页完成还书。
7. 使用管理员账号管理图书、人员、借阅记录及统计。

摄像头要求 localhost 或 HTTPS，以及浏览器授权。详细说明见 [使用说明](docs/USAGE.md)。

## 验证与构建

运行完整回归测试前，需要前后端依赖都已安装：扫码测试会使用前端的 ZXing 解码器。

```sh
npm test --prefix backend
npm run build --prefix frontend
```

测试使用临时数据库，不修改实际账号。覆盖权限与会话、密码恢复、模型加载与真实公开人脸样本比对、录入与撤销竞态、摄像头资源清理、真实码图解码、并发库存、失败回滚、重复借还及昵称变更。

前端构建输出至 `frontend/dist/`。模型及插画会触发体积提示，不影响构建完成。

## 配置与数据

| 环境变量 | 用途 | 默认值 |
| --- | --- | --- |
| `PORT` | 后端端口 | `3000` |
| `LIBRARY_DB_PATH` | SQLite 数据库文件 | `data/library.db` |
| `FACE_MODEL_DIR` | 服务端人脸模型目录 | `frontend/public/models/` |
| `FACE_KEY_PATH` | 人脸加密密钥文件 | 数据库同目录的 `face.key` |
| `VUE_APP_API_URL` | 前端 API 地址，构建/启动时设置 | `/api` |

后端直接读取进程环境变量，不会自动读取 `.env`。运行数据、会话、密钥、备份、依赖和构建产物均已加入忽略规则。备份及迁移需安全保留数据库和对应密钥；密钥丢失后可用密码登录重新录入。

部署时需提供 Node.js 后端、可写数据库目录和人脸模型目录，并通过 HTTPS 访问。GitHub Pages 只能承载静态前端，不能单独运行此系统的后端。
