# 实现设计

## 请求与权限

前端通过 Axios 调用 `/api`。密码或人脸验证成功后，服务端生成随机会话令牌，SQLite 只保存令牌 SHA-256 哈希。浏览器令牌放在当前标签页的 sessionStorage，请求携带 Bearer 令牌。服务端每次读取实际账号角色，普通用户不能调用管理接口；退出即撤销会话。

个人资料、人脸和个人借还接口都从会话获得账号 ID，不信任客户端指定的用户名或 userId。昵称只是可变展示和登录名称，历史关联使用固定 ID。

## 人脸验证

摄像头将画面缩放为 JPEG。服务端限制照片大小及尺寸，工作线程解码后使用 Tiny Face Detector、人脸轻量关键点与识别网络生成 128 维向量。无人脸、多张人脸或人脸过小会被拒绝。匹配使用欧氏距离，按当前昵称找到对应已录入账号，执行 1:1 验证。

特征使用随机 nonce 的 AES-256-GCM 加密。密码验证后的录入与删除仅作用于本人；更改会撤销其他会话。推理完成后在事务内再次确认会话、密码或人脸凭据未被撤销或替换。一个进程同时执行一项推理任务，45 秒超时终止并重建工作线程，API 主线程继续处理普通请求。

## 扫码与借还

本地 ZXing 解码二维码或常见条形码，得到编号文本。服务器按唯一 barcode 精确查询图书。前端显示书名和库存，用户确认后才提交借阅；服务器在事务内再次检查编号与图书一致。

借阅信息使用 user_id 和 book_id 外键。写事务使用独立 SQLite 连接与 BEGIN IMMEDIATE，库存以条件更新扣减，保证最后一本书不会被重复借出。不可变 borrow_requests 保存重试编号与原图书码，同一操作重试返回原借阅单。归还按个人 recordId 执行，重复归还不重复增加库存。

管理员修改总数时按已占用数量计算可借库存；有未归还或旧账占用的图书不能下架。下架使用软标记，保留历史。

## 旧账迁移

升级旧数据库前生成一致性 SQLite 备份。无法唯一确定用户或图书的历史记录保留并标为待核对，不猜测数字昵称；管理员可核实关联后恢复正常归还。无法解释的库存缺口使用 legacy_reserved 保留占用，异常库存导致迁移回滚。
